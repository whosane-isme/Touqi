# Ocarina of Time: idle benchmark, Touqi 2.0 (MSVC vs clang PGO) vs Frizti v3

RTX 5070, Ryzen 5 7600X, 1x resolution, GPU Fast, async GPU on. Each build launched fresh,
save loaded at the Kokiri spawn, then 1,800 presents with no input (`make bench IDLE=1800 N=2`).

## Why idle instead of the route

The route replays the recorded input once per presented frame, but Link moves per unit of
time. A slow build therefore walks him further (into the water, which costs frames) and a fast
one leaves him against a wall (which raises them): the route measures a different scene on
each build. Standing still shows the same view every run; the two runs of each build below
agree within 1 FPS, where route runs of the same build differed by up to 4.

## Results

| Build | Run 1 | Run 2 | Avg | p50 / p95 / p99 (ms) |
| --- | --- | --- | --- | --- |
| Frizti v3 (official, clang-cl + PGO + ThinLTO) | 46.9 | 45.8 | **46.4** | (no frame log) |
| Touqi 2.0, clang-cl 23 + PGO + ThinLTO | 42.3 | 42.8 | **42.6** | 21.3 / 23.4 / 24.6 |
| Touqi 2.0, MSVC | 39.6 | 39.5 | **39.6** | 22.7 / 25.6 / 26.9 |

Same session, route for reference: Touqi 2.0 PGO 37.6 / 41.2, Frizti v3 40.7 / 43.6.

## Conclusions

- The compiler recipe is worth +3 FPS (+8 %) on Touqi 2.0 and lowers p95/p99 by ~2 ms.
- Frizti v3 is still ~4 FPS (9 %) ahead. The profile (`eglantine.profdata`) was recorded on
  Frizti's code, so the functions Touqi 2.0 changed run unprofiled; the cherry-picked nx2
  commits are the other difference. Next: bisect them on the idle benchmark and record a
  profile of Touqi 2.0 itself.

## Follow-up: where the gap comes from

| Build | Idle runs | Avg |
| --- | --- | --- |
| Touqi 2.0 PGO without `nx2_switches.txt` (SPLIT=2, FENCE_BATCH=1 off) | 44.1 / 42.6 | 43.4 |
| Frizti v3 source (72e5ad6c22) built with `build-clang-pgo.cmd` | 42.8 / 40.3 | 41.5 |

Frizti's own source, built with our script, lands at Touqi 2.0's level, so the 3-4 FPS gap is in
the build, not in the commits Touqi 2.0 adds. The official Frizti v3 exe reports Clang 22.1.8
(ours: 23.1.5); AVX usage is the same, so `-march` is not it. Likely cause, not verified: the
repo's `eglantine.profdata` was written by LLVM 22 or Frizti used a newer profile than the repo's.
The `nx2_switches.txt` difference is within noise. #232 (hybrid-CPU thread placement) does nothing
on the 7600X (one efficiency class).
